# Quickstart: Professional Resume Website

## Prerequisites

- A modern browser.
- Owner-approved resume facts and permission to publish the selected contact details and links.
- Repository access to configure GitHub Pages when publishing.

## Preview locally

1. Open `docs/index.html` in a browser.
2. Confirm the page and `docs/styles.css` load correctly; verify links use relative paths.
3. Review the content against owner-approved source information. Remove optional sections without confirmed content; do not publish placeholder or invented personal details.
4. Check the page at narrow phone and wide desktop viewport sizes. Verify text readability, visible keyboard focus, usable navigation, and no horizontal overflow.
5. Use the browser's print or save-to-PDF action. Confirm the output contains the full resume without website-only controls, clipped content, or broken page breaks.
6. Review text and link contrast for WCAG 2.2 AA, keyboard access, heading structure, and accessible link names. Verify any motion respects reduced-motion settings.

## Publish with GitHub Pages

1. In the repository's GitHub Pages settings, select the default branch and the `/docs` publishing directory.
2. Wait for the Pages build to complete and open the published URL.
3. Confirm the deployed URL works at both a root site and a repository-subpath URL as applicable. Check that styles and optional local assets load and that no files outside `docs/` are exposed by the site.
4. Repeat the responsive, link, accessibility, and print checks against the published page before sharing it.

## Expected outcome

A visitor can identify the candidate's professional focus and locate the supplied experience, skills, education, and contact details quickly. The site remains readable without JavaScript, works on common phone and desktop widths, and produces a complete, legible printed or saved resume.
